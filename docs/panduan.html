Snapstrip / panduan02

Bagian 01

Project ini apa

Snapstrip adalah aplikasi photobooth digital. Aplikasi ini dipakai di satu layar, biasanya tablet besar, laptop, atau layar sentuh di bilik foto. Tamu datang, memasukkan kode akses yang diberikan operator, lalu memotret dirinya sendiri lewat kamera perangkat itu.

Setelah enam potret terkumpul, tamu memilih susunan cetak. Aplikasi menyusun keenam foto menjadi satu lembar strip, mengirimkannya ke email tamu, dan mengunggah semua foto ke Google Drive dalam satu folder yang namanya memakai kode akses tadi. Folder itu yang nanti dipakai operator untuk mencetak atau menyerahkan file asli.

Masalah yang dipecahkan

Photobooth manual biasanya bergantung pada satu orang yang menekan tombol dan menyalin file foto ke flashdisk. Di sini pembagiannya jelas: tamu melayani dirinya sendiri, operator hanya membagikan kode, dan file tersimpan otomatis tanpa ada yang menyalin manual.

Alur singkatnya

01 / kode Operator membuat kode enam karakter. Tamu memasukkan kode dan email.
›
02 / potret Enam kali potret dengan hitungan tiga detik. Foto bisa diulang.
›
03 / cetak Pilih susunan strip. Aplikasi menyusun file cetak.
›
04 / kirim Email berisi strip, Drive berisi folder semua foto.

Istilah yang dipakai

Kode akses adalah enam huruf atau angka yang membuka satu sesi. Sesi adalah satu kali jalan dari memasukkan kode sampai foto terkirim. Strip adalah lembar hasil susunan foto yang siap dicetak.

Bagian 02

Bagian yang menyusun aplikasi

Aplikasi ini satu project, bukan dua yang terpisah. Halaman yang dilihat tamu dan data yang disimpan berada di tempat yang sama, sehingga tidak ada alamat server kedua yang perlu diurus.

Laravel 13 (PHP)

Menyimpan kode akses, mencatat sesi foto, menyusun file strip dengan GD, mengirim email, dan mengunggah ke Google Drive. Semua alamat API ada di bawah /api/v1.

React 19 (JavaScript)

Semua layar yang dilihat tamu dan staff. Dibangun dengan Vite, gaya memakai Tailwind 4 dan satu set token warna di resources/css/tokens.css.

MySQL

Menyimpan tabel users, access_codes, booth_orders, dan tabel bawaan Laravel. Bisa dilihat langsung lewat phpMyAdmin Laragon.

Google Drive

Menyimpan semua foto dan strip per sesi. Satu folder per kode akses. Sambungannya memakai service account, jadi tidak ada login ulang.

Yang perlu ada di komputer

Perangkat lunakVersiUntuk apa

Kalau memakai Laragon

Semua perangkat lunak di atas sudah terpasang. Yang sering perlu dinyalakan hanya dua ekstensi PHP: gd dan pdo_mysql. Caranya dibuka di menu PHP, Extensions, lalu centang keduanya.

Kamera dan browser

Akses kamera hanya diberikan browser pada alamat yang dianggap aman, yaitu localhost atau situs ber-https. Jadi saat mencoba di komputer sendiri, buka lewat http://localhost:8000, bukan lewat alamat IP seperti 192.168.x.x. Kalau nanti dipasang di bilik foto dengan tablet lain, server harus memakai HTTPS.

Menjalankan: persiapan

Buka terminal di folder project. Semua perintah di bawah dijalankan dari folder itu. Kalau memakai Laragon, klik kanan pada folder project lalu pilih Terminal Here.

1

Pasang paket PHP

Sekali saja, atau setiap kali ada perubahan pada composer.json.

composer install
2

Siapkan file pengaturan

Salin .env.example menjadi .env, lalu isi kunci aplikasi. File .env tidak pernah ikut terkirim ke GitHub karena berisi kata sandi. 

copy .env.example .env
php artisan key:generate
3

Buat database kosong

Buka phpMyAdmin di http://localhost/phpmyadmin, pilih New, beri nama snapstrip, lalu Create. Pastikan isi .env cocok dengan nama itu. 

DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=snapstrip

DB_PASSWORD=

Bangun tabel dan akun awal

Perintah ini membuat semua tabel, akun staff, dan lima kode akses contoh. migrate:fresh menghapus isi database lebih dulu, jadi jangan dipakai kalau sudah ada data sungguhan. 

php artisan migrate:fresh --seed
php artisan storage:link
Tentang storage:link

Perintah kedua membuat tautan supaya foto di storage/app/public bisa dibuka lewat browser di alamat /storage/.... Cukup dijalankan sekali per komputer.

Akun staff dan kode akses

Ada dua peran staff. Keduanya masuk dari tombol Staff di pojok kanan atas layar tamu. Setelah data awal dibuat, dua akun ini tersedia:

PeranNama penggunaKata sandiTugas

Wajib diganti

Kata sandi password hanya untuk mencoba di komputer sendiri. Sebelum dipakai di acara sungguhan, ganti lewat perintah di bawah. 

php artisan tinker
>>> App\Models\User::where('username', 'admin')
...     ->update(['password' => Hash::make('kata-sandi-baru')]);

Membuat kode akses

Masuk sebagai admin, lalu tekan tombol Buat kode. Kode baru muncul sebagai kartu kertas besar dengan tombol salin. Kode ini yang ditunjukkan atau dibacakan ke tamu.

Sifat kode

  • Enam karakter, huruf besar dan angka.
  • Berlaku untuk satu sesi saja.
  • Langsung hangus setelah dipakai.
  • Email tamu tercatat bersama kode itu.

Kalau kode ditolak

  • Kode sudah dipakai tamu lain.
  • Kode salah ketik, perhatikan huruf O dan angka 0.
  • Kode sudah dihapus dari database.
  • Solusinya: buat kode baru dari akun admin.
Masa berlaku sesi

Satu sesi berjalan enam menit, dihitung dari saat kode diterima sampai tombol cetak ditekan. Kalau waktu habis, layar kembali ke halaman kode dan kode yang tadi sudah hangus. Tamu perlu kode baru. Angka ini bisa diubah di config/booth.php pada baris session_seconds.

Bagian 05

Alur tamu: kode dan potret

Halaman awal

Layar menyambut dengan tulisan Snapstrip dan tombol Mulai sesi. Di bawahnya ada keterangan jumlah potret, lama sesi, dan harga mulai. Tiga lembar strip kertas di sisi kanan hanya hiasan, bukan tombol.

Memasukkan kode

Tamu mengetik enam karakter kode, lalu email. Kotak kode otomatis mengubah huruf menjadi besar dan membuang karakter yang tidak perlu. Tombol Lanjut ke kamera baru menyala setelah kode lengkap dan email terlihat benar. Di sisi kanan ada pratinjau tiket yang ikut terisi sambil mengetik, jadi tamu bisa memastikan kodenya tidak salah.

Mengambil potret

Kamera menyala dengan gambar dicerminkan, seperti bercermin. Ada dua cara memotret:

  • Tekan tombol bulat besar di bawah gambar kamera.
  • Atau sentuh di mana saja pada gambar kamera.

Setelah ditekan, muncul hitungan tiga, dua, satu, lalu layar berkedip putih tanda foto tersimpan. Jumlah foto yang sudah terisi terlihat di panel Kontak cetak.

Mengulang satu foto

Ketuk salah satu kotak kecil di panel kontak cetak. Kotak itu diberi garis kuning, artinya foto berikutnya akan menggantikan foto tersebut. Tekan tombol potret sekali lagi. Kalau berubah pikiran, ketuk kotak yang sama untuk membatalkan.

Tampilan menyesuaikan layar

Di ponsel, panel foto pindah ke bawah kamera. Di tablet, panel pindah ke samping kamera. Di layar lebar, muncul panel kiri berisi sisa waktu dan jumlah potret, plus panel kanan untuk memilih foto yang mau diulang.

Bagian 05, lanjutan

Alur tamu: bingkai dan selesai

Memilih susunan cetak

Setelah enam foto terisi, tombol Pilih bingkai menyala. Di layar berikutnya ada tiga pilihan:

NamaBentukHarga
Strip SixSatu kolom, enam potret, seperti film stripRp35.000
Grid SixDua kolom tiga barisRp35.000
Postcard FourDua kolom dua baris, memakai empat foto pertamaRp30.000

Apa pun pilihannya, keenam foto tetap dikirim penuh ke email dan Drive. Susunan hanya menentukan bentuk lembar yang dicetak.

Selesai

Tekan Cetak dan kirim. Layar berganti ke struk hasil: strip kecil sebagai pratinjau, kode sesi, jumlah potret, nama bingkai, dan total. Kalau Google Drive sudah tersambung, muncul tautan folder Drive. Tombol Sesi baru mengembalikan layar ke halaman awal untuk tamu berikutnya.

Apa yang terjadi di belakang layar

  1. Keenam foto dikirim ke server, masing-masing diperiksa jenis dan ukurannya.
  2. Server menyimpan foto ke folder sesi di dalam storage/app/public.
  3. Server menyusun file strip sesuai bingkai yang dipilih.
  4. Email berisi tautan dan lampiran strip dikirim ke alamat tamu.
  5. Folder baru dibuat di Google Drive, diisi enam foto dan satu strip.
  6. Tautan folder disimpan, lalu ditampilkan di layar selesai.
Kalau waktu habis

Layar kembali ke halaman kode dan kode sebelumnya sudah hangus. Berikan kode baru. Foto yang sudah diambil tidak tersimpan karena sesinya dianggap gagal.

Bagian 06

Alur admin dan operator

Masuk

Tekan tombol Staff di pojok kanan atas. Pilih peran, lalu isi nama pengguna dan kata sandi. Kalau salah, kolom yang bermasalah diberi garis merah dan muncul satu pemberitahuan di bawah layar, bukan jendela peringatan browser.

Dashboard admin

Isinya tiga hal:

  • Tiga angka di atas: total kode, kode aktif, kode terpakai.
  • Tombol Buat kode untuk membuat kode baru.
  • Daftar kode berisi kode, status, email pemakai, waktu dipakai, dan waktu dibuat.

Kode yang baru dibuat muncul sebagai kartu kertas besar di atas daftar, lengkap dengan tombol Salin. Kartu itu tetap ada sampai kamu membuat kode berikutnya atau menekan keluar.

Dashboard operator

Hampir sama, tetapi tanpa tombol membuat kode. Operator hanya memantau: berapa kode aktif, berapa yang sudah terpakai, siapa pemakainya, dan kapan dipakai. Ada tombol Muat ulang untuk mengambil data terbaru tanpa keluar dari halaman.

Admin cocok untuk

  • Kasir atau penanggung jawab acara.
  • Orang yang membagikan kode ke tamu.
  • Orang yang boleh menambah kuota sesi.

Operator cocok untuk

  • Petugas yang menjaga bilik foto.
  • Orang yang perlu memeriksa kode tanpa bisa membuatnya.
  • Shift kedua yang hanya melanjutkan sesi.

Membaca status kode

StatusArtinyaTindakan
aktifBelum dipakai, bisa diberikan ke tamuTidak perlu apa-apa
terpakaiSudah dipakai satu sesiBuat kode baru untuk tamu berikutnya
Satu kode satu tamu

Kode yang sudah terpakai tidak bisa diaktifkan kembali dari layar. Ini disengaja supaya tidak ada dua tamu memakai kode yang sama. Kalau tamu gagal di tengah jalan karena waktu habis, berikan kode baru.

Bagian 07

Google Drive: membuat kunci

Bagian ini opsional. Tanpa sambungan Google, semua foto tetap tersimpan di server dan tetap dikirim lewat email. Yang hilang hanya salinan di Drive.

Caranya memakai service account, yaitu akun robot milik Google yang dipakai server untuk mengunggah file. Akun ini tidak punya kotak masuk dan tidak pernah minta login ulang, cocok untuk server yang menyala terus.

1

Buat project di Google Cloud Console

Buka console.cloud.google.com, masuk dengan akun Google kamu, lalu buat project baru. Namanya bebas, misalnya Snapstrip Booth.

2

Aktifkan Google Drive API

Masuk ke menu APIs & Services, pilih Library, cari Google Drive API, lalu tekan Enable.

3

Buat service account

Buka IAM & Admin, pilih Service Accounts, tekan Create Service Account. Beri nama, misalnya snapstrip-uploader. Peran di project boleh dikosongkan, karena izinnya nanti diberikan langsung di folder Drive.

4

Unduh kunci JSON

Buka service account yang baru dibuat, masuk ke tab Keys, tekan Add key, pilih Create new key, lalu pilih JSON. Sebuah file .json akan terunduh.

Simpan file itu di folder project dengan nama storage/app/google/service-account.json. Folder ini sudah diabaikan oleh Git, jadi kuncinya tidak akan ikut terkirim ke GitHub.

Jangan bagikan

File service-account.json adalah kunci. Siapa pun yang memegangnya bisa mengunggah ke Drive kamu. Kalau file itu terlanjur terkirim ke orang lain, buka halaman Keys di Google Cloud, hapus kuncinya, lalu buat yang baru.

Bagian 07, lanjutan

Google Drive: menyambungkan

5

Bagikan folder Drive

Buat satu folder di Google Drive sebagai tempat semua sesi, misalnya Snapstrip Hasil. Buka file JSON tadi, cari baris client_email. Alamatnya seperti snapstrip-uploader@nama-project.iam.gserviceaccount.com.

Klik kanan folder Drive, pilih Share, tempel alamat itu, dan beri akses Editor. Tanpa langkah ini unggahan akan ditolak dengan pesan izin.

6

Isi file .env

Ambil ID folder dari alamatnya. Kalau alamatnya drive.google.com/drive/folders/1AbCdEfGhIjK, maka ID-nya 1AbCdEfGhIjK. 

GOOGLE_DRIVE_FOLDER_ID=1AbCdEfGhIjK

Kalau file JSON disimpan di tempat lain, tambahkan juga baris GOOGLE_SERVICE_ACCOUNT_JSON berisi alamat lengkap file itu.

7

Bersihkan cache lalu coba satu sesi

php artisan config:clear

Jalankan satu sesi penuh. Setelah selesai, folder baru akan muncul di Drive dengan nama kode akses di depan, misalnya NUJJDX SNAP-XXXXXXXX. Di dalamnya ada enam foto dan satu file strip.

Kalau unggahan gagal

Kegagalan Drive tidak membatalkan sesi. Foto tetap tersimpan di server dan email tetap dikirim. Pesan sebabnya dicatat di storage/logs/laravel.log dengan awalan Upload Drive gagal. Tiga penyebab paling sering: folder belum dibagikan ke service account, Drive API belum diaktifkan, atau ID folder salah.

Bagian 07, lanjutan

Memastikan sambungan Google benar

Kalau ingin memeriksa tanpa harus memotret enam kali, jalankan perintah berikut. Perintah ini hanya membaca konfigurasi, tidak mengunggah apa pun. 

php artisan tinker
>>> app(App\Services\GoogleDriveUploader::class)->isConfigured()

Hasil true berarti file kunci ada dan ID folder sudah terisi. Hasil false berarti salah satunya belum siap.

Apa yang dikirim ke Drive

Isi folderKeterangan
potret-1.jpg sampai potret-6.jpgEnam foto asli, urutan sesuai pengambilan
strip-SNAP-XXXXXXXX.jpgLembar siap cetak, sudah disusun sesuai bingkai

Tautan folder disimpan di kolom drive_link pada tabel booth_orders, ikut tampil di layar selesai, dan ikut disertakan dalam email tamu.

Email

Pada pemasangan baru, email tidak benar-benar dikirim. Isinya ditulis ke storage/logs/laravel.log supaya aman dites tanpa alamat sungguhan. Untuk mengirim sungguhan, isi pengaturan SMTP di .env: 

MAIL_MAILER=smtp
MAIL_HOST=smtp.gmail.com
MAIL_PORT=587
MAIL_USERNAME=alamat@gmail.com
MAIL_PASSWORD=kata-sandi-aplikasi
MAIL_ENCRYPTION=tls
MAIL_FROM_ADDRESS=alamat@gmail.com
MAIL_FROM_NAME="Snapstrip"

Untuk Gmail, MAIL_PASSWORD bukan kata sandi akun biasa, melainkan kata sandi aplikasi yang dibuat di pengaturan keamanan akun Google. Setelah mengubah .env, jalankan php artisan config:clear.

Bagian 08

Melihat data lewat phpMyAdmin

phpMyAdmin adalah halaman web bawaan Laragon untuk melihat isi database tanpa menulis perintah. Buka http://localhost/phpmyadmin, lalu pilih database snapstrip di daftar sebelah kiri.

Tiga tabel yang penting

access_codes

Semua kode akses. Kolom code berisi enam karakter, status berisi active atau used, used_email berisi email tamu, dan used_at berisi waktu kode dipakai.

booth_orders

Satu baris untuk satu sesi foto. Kolom yang sering dilihat: public_id (kode sesi seperti SNAP-XXXXXXXX), email, layout_id (bingkai yang dipilih), shot_count (jumlah foto), amount (harga), strip_path (lokasi file strip), drive_link (tautan folder Drive), dan email_sent_at (waktu email terkirim).

users

Akun staff. Kolom username untuk masuk, role berisi admin atau operator, dan password berisi kata sandi yang sudah diacak. Kata sandi asli tidak bisa dibaca, hanya bisa diganti.

Mengganti kata sandi staff

Cara paling mudah tetap lewat php artisan tinker di Bagian 04, karena phpMyAdmin tidak bisa membuat acakan kata sandi Laravel. Kalau tetap ingin dari phpMyAdmin, jalankan SQL berikut setelah mengganti teks di dalam tanda kutip dengan hasil acakan dari tinker. 

UPDATE users
SET password = 'hasil-acakan-dari-tinker'
WHERE username = 'admin';
Melihat file foto

Foto tidak disimpan di database, hanya alamatnya. File aslinya ada di folder storage/app/public/photos. Untuk membukanya lewat browser, pastikan php artisan storage:link sudah pernah dijalankan, lalu akses lewat /storage/photos/....

Bagian 09, lanjutan

Mengubah pengaturan dan warna

Jumlah potret dan bingkai

Semua pengaturan itu ada di config/booth.php. Kalau shots_required diubah dari 6 menjadi 4, tampilan otomatis menyesuaikan karena jumlah kotak diambil dari API. Setelah mengubah konfigurasi, jalankan php artisan config:clear. 

'shots_required' => 6,
'session_seconds' => 6 * 60,

'layouts' => [
    [
        'id' => 'strip-six',
        'name' => 'Strip Six',
        'columns' => 1,
        'rows' => 6,
        'shots_used' => 6,
        'price' => 35000,
        // ...
    ],
],

Warna

Semua warna ada di resources/css/tokens.css. Mengganti nilai --color-amber akan mengubah seluruh tombol, garis, dan aksen di aplikasi tanpa menyentuh komponen satu per satu.

TokenDipakai untuk
--color-inkLatar utama
--color-paperTeks terang dan kertas strip
--color-amberTombol utama dan aksen
--color-clayKesalahan dan status terpakai
--color-sageStatus aktif dan berhasil
--font-displayJudul besar

Semua komponen hanya menyebut nama token, tidak pernah menulis kode warna langsung. Jadi satu perubahan di file token langsung berlaku di seluruh halaman, dan tidak ada bagian yang tertinggal dengan warna lama.

Melihat catatan kesalahan

Semua kejadian penting ditulis ke storage/logs/laravel.log. Buka file itu dan baca bagian paling bawah. Setiap baris punya penanda waktu dan kode permintaan yang sama dengan balasan API, jadi mudah dilacak.

Kalau bingung

Coba jalankan ulang dari langkah paling awal secara berurutan: composer install, php artisan migrate:fresh --seed, php artisan storage:link, npm install, php artisan serve, lalu npm run dev. Sebagian besar masalah hilang dengan urutan itu.

Catatan keamanan

Aplikasi ini dibuat untuk dipakai di dalam bilik foto, bukan untuk internet terbuka tanpa pengawasan. Beberapa hal perlu diperhatikan sebelum dipakai di acara sungguhan.

Sebelum hari acara

  • Ganti kata sandi admin dan operator.
  • Pastikan .env dan file kunci Google tidak ikut terkirim ke mana pun.
  • Pakai HTTPS kalau layar tamu bukan komputer server itu sendiri.
  • Uji satu sesi penuh, dari kode sampai email masuk.
  • Siapkan beberapa kode cadangan.

Yang sudah dijaga oleh aplikasi

  • Kode akses hanya bisa dipakai satu kali, dicek di dalam transaksi database.
  • Sesi staff disimpan di cookie yang tidak bisa dibaca JavaScript.
  • Setiap permintaan yang mengubah data membawa token pelindung dari Laravel.
  • Percobaan masuk dibatasi, sehingga tidak bisa dicoba ribuan kali.
  • Pesan kesalahan server tidak menampilkan isi database atau jejak kode.
  • Ukuran dan jenis file foto diperiksa sebelum disimpan.

Yang perlu dijaga oleh manusia

  • Jangan menampilkan dashboard admin ke tamu.
  • Jangan membagikan file kunci Google lewat chat.
  • Hapus foto lama secara berkala dari Drive dan server kalau tidak diperlukan.
  • Simpan email tamu seperlunya, karena itu data pribadi.

Ringkasan dalam satu paragraf

Snapstrip adalah bilik foto digital berbasis Laravel dan React. Operator membuat kode akses, tamu memakai kode itu untuk membuka satu sesi enam menit, memotret enam kali, memilih susunan cetak, lalu menerima strip lewat email sementara semua foto tersimpan di Google Drive. Data sesi bisa dilihat di phpMyAdmin, dan seluruh tampilan serta warna diatur dari satu file token.
